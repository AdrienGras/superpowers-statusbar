# superpowers-statusbar v0.1.1 (fiabilité) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close tickets #2–#11 and #15 of superpowers-statusbar: detector and hook robustness, narrow-width display, test hygiene, and five behaviour decisions (#3 inline TDD wording, #4 slash-typed skills, #5 finishing menu, #6 subagent skills, #7 `agent.spawn`).

**Architecture:** Pure core in `src/` (detectors → actions → reducer → view models), engine layer in `hooks/` (`register.tsx` wires hooks, `runtime.ts` observes through an `EnginePort`). New engine sources (`agent.spawn`, `command.run`) become new `ObservedEvent` kinds handled by the detector; behaviour rules live in the detector (wording of superpowers 7.0.0) and the reducer (run rules).

**Tech Stack:** TypeScript (erasable only), Claude Code mod API `claude-code` (Claude Code 2.1.296), tests with `claude-code/testing`, Node 24 for `scripts/`.

**Spec:** `docs/superpowers/specs/2026-10-14-v0.1.1-fiabilite-design.md` (this session's decisions), on top of the reference design `docs/superpowers/specs/2026-10-13-superpowers-statusbar-design.md`. Ticket details: `gh issue view <n> -R AdrienGras/superpowers-statusbar`.

- Displayed text (band, pane, notifications, command output, README, dev scripts' output) is English.

- Colours: `ThemeKey`s only, through the existing `Tone`s.
- Dispatch-description heuristics stay bilingual (EN/FR).
- No client data in git: fixtures stay synthetic.

## Review Focus

- A real session in French: the keep-the-branch report and dispatch descriptions worded in French must behave like the English ones (Task 5 tests a French keep report and a French menu line; Task 3 tests a French final-review description still matches).
- Orchestrator mode end to end: a main loop dispatches one free-described subagent that runs SDD then finishing; implementers inside it must not move the run (Task 4 replays that run).
- A dispatch seen by both `agent.spawn` and the `Agent` tool call must count once, for background and foreground agents alike (Task 6 tests both orders of arrival).
- `--resume` of a session whose transcript holds a subagent's `Skill` call: the rebuild must not reset or move the run from it (Task 4 tests `messagesToEvents` + replay).
- A very narrow terminal: no band, waiting or not, is ever wider than `columns`, down to 1 column (Task 2 tests every width 1–12 and the final-review/finishing bands).
